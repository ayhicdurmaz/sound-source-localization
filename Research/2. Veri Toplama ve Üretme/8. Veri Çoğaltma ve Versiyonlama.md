Bu proje, fiziksel dünyanın zorluklarını (rüzgar, gürültü, çoklu kaynak) laboratuvar ortamında simüle ederek ve toplanan verileri profesyonel araçlarla yöneterek, modelin **"ezberlemesini" (overfitting)** önlemeyi ve **"genelleştirme" (generalization)** yeteneğini artırmayı hedefler.

### 1. Veri Çoğaltma (Data Augmentation) Teknikleri

7+1 Dairesel Mikrofon Dizisi mimarisine ve SELD problemine özgü, eğitim sırasında (On-the-fly) veya eğitim öncesinde (Offline) uygulanacak teknikler şunlardır:

#### **A. Akustik Gürültü Enjeksiyonu (Noise Injection)**

Saha kayıtlarında temiz "Ground Truth" verisi elde etmek zordur. Bu nedenle model, temiz sinyallere sentetik gürültü eklenerek eğitilecektir.

- **Yöntem:** Temiz drone veya insan sesi kayıtlarına, `metadata.csv` dosyasındaki `snr_db` hedefine uygun olarak **UrbanSound8K** veya saha kayıtlarından elde edilen "Arka Plan Gürültüsü" eklenir.
    
- **Uygulama:** Sinyal-Gürültü Oranı (SNR) rastgele olarak -5 dB ile +20 dB arasında değiştirilerek veri seti 5 katına çıkarılır. Bu yaklaşım, Wu ve ark. 2 tarafından düşük SNR koşullarında başarımı artırdığı kanıtlanmış bir yöntemdir.
    

#### **B. Dairesel Kaydırma (Spatial Rotation / Channel Swapping)**

Bu, dairesel dizilere özgü en güçlü çoğaltma yöntemidir. Dizi simetrik olduğu için, ses kaynağını fiziksel olarak döndürmek yerine, mikrofon kanallarını kaydırmak aynı matematiksel etkiyi yaratır.

- **Mantık:** 7 çevresel mikrofon (Kanal 0-6) dairesel bir düzendedir. Sinyalleri 1 adım kaydırmak (Kanal 0 verisini Kanal 1'e, Kanal 1'i Kanal 2'ye... aktarmak), ses kaynağını sanal olarak $360 / 7 \approx 51.4$ derece döndürmek demektir.
    
- **Dikkat:** Merkez mikrofon (Kanal 7) referans olduğu için bu kaydırma işlemine **dahil edilmez**.
    
- **Kazanç:** Tek bir fiziksel kayıt ile 7 farklı açıdan (Azimut) veri elde edilmiş olur. Veri seti **7 katına** çıkar.
    

#### **C. Zaman ve Frekans Maskeleme (SpecAugment)**

Modelin belirli bir frekansa veya zaman dilimine aşırı odaklanmasını engellemek için Spektrogram veya GCC-PHAT haritaları üzerinde rastgele bloklar "silinir" (sıfırlanır).

- **Time Masking:** Drone sesinin kesintili gelmesi durumunu simüle eder.
    
- **Frequency Masking:** Belirli frekanslardaki (örn. motor harmonikleri) kaybı simüle eder.

### 2. Veri Versiyonlama ve Yönetimi (DVC & Git LFS)

Ses dosyaları (WAV) ve model ağırlıkları (PTH/H5) büyük boyutlu (Binary Large Object) olduğu için standart Git depolarında saklanamaz. Projenin sürdürülebilirliği için **DVC (Data Version Control)** aracı kullanılacaktır.

#### **A. Neden DVC?**

- **Kod ve Veri Senkronizasyonu:** "Modelimin %95 başarı verdiği versiyon hangi veri setiyle eğitilmişti?" sorusunun cevabını garanti altına alır. `git checkout v1.0` dediğinizde hem kodunuz hem de o koda ait 50 GB'lık veri seti otomatik olarak geri yüklenir.
    
- **Depolama Bağımsızlığı:** Veriler GitHub'da değil, sizin belirlediğiniz ucuz ve geniş bir alanda (Google Drive, AWS S3, Local NAS veya Üniversite Sunucusu) tutulur. GitHub sadece küçük `.dvc` referans dosyalarını tutar.
    

#### **B. DVC İş Akışı (Workflow)**

1. **Başlatma:**
    
    Bash
    
    ```
    dvc init
    git commit -m "DVC kurulumu"
    ```
    
2. Veri Ekleme:
    
    Ham verileri takibe almak için:
    
    Bash
    
    ```
    dvc add data/raw_recordings
    git add data/raw_recordings.dvc .gitignore
    git commit -m "Ham veri seti v1 eklendi"
    ```
    
3. **Uzak Depolama Ayarı (Örn: Yerel Sunucu veya Drive):**
    
    Bash
    
    ```
    dvc remote add -d myremote /mnt/server/storage/tubitak_data
    dvc push
    ```
    
4. Versiyonlama:
    
    Yeni veri toplandığında veya işlendiğinde:
    
    Bash
    
    ```
    dvc add data/processed_gcc_phat
    git commit -m "GCC-PHAT öznitelikleri güncellendi"
    git tag -a "v2.0_saha_verisi"
    dvc push
    ```
    

#### **C. Git LFS (Large File Storage)**

DVC kurulumu karmaşık gelirse veya sadece doküman/rapor gibi orta boyutlu dosyalar (100 MB altı) versiyonlanacaksa Git LFS kullanılabilir. Ancak 100 GB'lık ses verisi için DVC şarttır. Bu projede **Kod ve Dokümanlar için Git**, **Büyük Veri ve Modeller için DVC** hibrit yapısı kullanılacaktır.

### 3. Entegre Veri Yönetim Hattı (Integrated Pipeline)

Veri çoğaltma ve versiyonlama süreçleri, otomatik bir boru hattı (pipeline) üzerinde çalışarak manuel hataları ortadan kaldırır.

1. **Ingestion (Giriş):** Saha kayıtları `data/raw` klasörüne atılır ve `dvc add` ile kilitlenir.
    
2. **Preprocessing (İşleme):** Python scripti çalışır; temizleme, DC offset giderme ve 16 kHz örnekleme dönüşümü yapar. Çıktı `data/interim` klasörüne yazılır.
    
3. **Augmentation (Çoğaltma):** İşlenmiş veriye gürültü ekleme ve kanal kaydırma (rotation) uygulanır. Veri seti 10-20 kat büyür. Çıktı `data/processed` klasörüne yazılır.
    
4. **Feature Extraction:** GCC-PHAT haritaları çıkarılır ve eğitim için `.npy` olarak kaydedilir.
    
5. **Versioning:** Tüm bu aşamaların çıktıları DVC ile versiyonlanır. Böylece bir hata yapıldığında "sadece işlenmiş veriyi" geri almak mümkündür, ham veriye dönmeye gerek kalmaz.
